We are announcing a new Crystal release 1.22.3 with important security patches,
regression fixes, and normal bug fixes.

See [the release notes of 1.22.0](2026-10-12-1.22.0-released.md) for all the
changes introduced in Crystal 1.22.

Pre-built packages are available on [GitHub
Releases](https://github.com/crystal-lang/crystal/releases/tag/1.22.3) and our
official distribution channels. See
[crystal-lang.org/install](https://crystal-lang.org/install/) for installation
instructions.

## Stats

This release includes [14 changes since
1.22.2](https://github.com/crystal-lang/crystal/pulls?q=is%3Apr+milestone%3A1.22.3)
by 4 contributors. We thank all the contributors for all the effort put into
improving the language! ❤️

## Changes

Below we list the most significant, security-related changes.
For more details, visit the [full
changelog](https://github.com/crystal-lang/crystal/blob/master/doc/changelogs/v1.22.md).

### `Socket` reliably enforces port number range

Creating a socket on port higher than 65535 can no longer succeed with a truncated
port number ([#17848]).
On some systems, the following snipped would create a socket on port 8080 prior
to this patch:

```cr
TCPServer.new(73616).local_address # raises Socket::Addrinfo::Error
```

- Security Advisory: [GHSA-6q3x-6xhw-wfxp]

_Thanks, [@straight-shoota]_

[GHSA-6q3x-6xhw-wfxp]: https://github.com/crystal-lang/crystal/security/advisories/GHSA-6q3x-6xhw-wfxp
[#17848]: https://github.com/crystal-lang/crystal/issues/17848

### HTTP message validation

We fixed a couple of bugs in the HTTP message parser which previously accepted
some invalid inputs.
This could potentially result in a protocol desync with a parser that
interprets these invalid message in a different way.

- control whitespace before field value in HTTP headers ([#17903])
- `HTTP::ChunkedContent` validates the chunk-line ([#17898])
- validate `Content-Length` header ([#17902])

These invalid message now always result in an error.

- Advisory: [GHSA-j97w-qwpv-7cfv]

_Thanks, [@ysbaddaden]_

[GHSA-j97w-qwpv-7cfv]: https://github.com/crystal-lang/crystal/security/advisories/GHSA-j97w-qwpv-7cfv
[#17898]: https://github.com/crystal-lang/crystal/issues/17898
[#17902]: https://github.com/crystal-lang/crystal/issues/17902
[#17903]: https://github.com/crystal-lang/crystal/issues/17903

### HTTP `Connection` header

The `close` token in `Connection` header now always closes the connection, even
if there are other values beside it ([#17904]).

_Thanks, [@ysbaddaden]_

[#17904]: https://github.com/crystal-lang/crystal/issues/17904

### `IO::Delimited` delimiter mismatch

Fix `IO::Delimited` matching after a fragmented delimiter mismatch ([#17916]).

_Thanks, [@ysbaddaden]_

- Advisory: [GHSA-jgv7-2p84-pm39]

[GHSA-jgv7-2p84-pm39]: https://github.com/crystal-lang/crystal/security/advisories/GHSA-jgv7-2p84-pm39
[#17916]: https://github.com/crystal-lang/crystal/issues/17916

### `Enum.parse?` regression could lead to out-of-bounds writes and crash

`Enum.parse?` no longer crashes if the input exceeds max bytesize buffer limit
 ([#17836]). This is a regression from 1.22.0.

- Advisory: [GHSA-5425-p3gq-r48v]

_Thanks, [@straight-shoota]_

[GHSA-5425-p3gq-r48v]: https://github.com/crystal-lang/crystal/security/advisories/GHSA-5425-p3gq-r48v
[#17836]: https://github.com/crystal-lang/crystal/issues/17836
