### Breaking: Exit on pipe error

Crystal processes exit immediately when writing to STDOUT or STDERR fails with `EPIPE`. This closely resembles the default behaviour of the `SIGPIPE` signal.
Previously, the failing write would raise `IO::Error`, which typically print an error message and exits. This error message is now removed ([#17335]).
You can opt out of this behaviour by setting `STDOUT.exit_on_broken_pipe = false`.

_Thanks, [@straight-shoota]_

[#17335]: https://github.com/crystal-lang/crystal/issues/17335

### Constants with type declarations

Constants can have type declarations ([#16951]):

```cr
module Foo
  BAR : Int32 = 1
  BAZ : String = ""
  QUX : Int64 = 123 # autocasts 123 to Int64
end
```

_Thanks, [@stakach]_

[#16951]: https://github.com/crystal-lang/crystal/issues/16951

### Eventloop

By default, the event loop now uses `epoll` on Solaris ([#17370]) and `kqueue` on all BSD targets ([#17421], [#17420]).
That means all targets support a native event loop and the `libevent` fallback is starting to become technically obsolete. It's only available as opt-in.

_Thanks, [@ysbaddaden]_

[#17370]: https://github.com/crystal-lang/crystal/issues/17370
