We are announcing a new Crystal release 1.22.0 with several new features and bug
fixes.

Pre-built packages are available on [GitHub
Releases](https://github.com/crystal-lang/crystal/releases/tag/1.22.0) and our
official distribution channels. See
[crystal-lang.org/install](https://crystal-lang.org/install/) for installation
instructions.

## Stats

This release includes [251 changes since
1.21.1](https://github.com/crystal-lang/crystal/pulls?q=is%3Apr+milestone%3A1.22.0)
by 33 contributors. We thank all the contributors for all the effort put into
improving the language! ❤️

## Changes

Below we list the most remarkable changes in the language, compiler, and stdlib.
For more details, visit the [full
changelog](https://github.com/crystal-lang/crystal/blob/master/doc/changelogs/v1.22.md).

### Breaking: Exit on pipe error

Crystal processes exit immediately when writing to STDOUT or STDERR fails with `EPIPE`.
This closely resembles the default behaviour of the `SIGPIPE` signal.
Previously, the failing write would raise `IO::Error`, which typically prints
an error message and exits. This error message is now removed ([#17335]).

You can opt out of this behaviour with `STDOUT.exit_on_broken_pipe = false`.

_Thanks, [@straight-shoota]_

[#17335]: https://github.com/crystal-lang/crystal/issues/17335

### Constants with type declarations

Constants can have type declarations ([#16951]).
They work exactly as you would expect the combination of constants and type declarations to be.

```cr
module Foo
  BAR : Int32 = 1
  BAZ : String = ""
  QUX : Int64 = 123 # autocasts 123 to Int64
end
```

_Thanks, [@stakach]_

[#16951]: https://github.com/crystal-lang/crystal/issues/16951

### `aarch64-linux` promoted to Tier 1

The targets `aarch64-linux-gnu` and `aarch64-linux-musl` moved from Tier 2 to Tier 1.
The only missing piece was that we were lacking official builds, but we have that since 1.19.

### Breaking: `Process.fork` removed

`Process.fork` had been deprecated sine before 1.0 and now we finally removed it ([#17367])

### DWARF refactor

We completely revamped DWARF parsing to enhance performance and reduce memory usage.
The DWARF parser now scans sections on demand ([#17283]) and builds an efficient index table once ([#17410], [#17455]), which results in blazingly fast look ups.
Decoded backtrace lines are cached in an LRU cache ([#17285]).

Also added aupport for DWARF 5 features `DW_FORM_addrx<n>` and `DW_FORM_strx<n>` ([#17445]).

_Thanks, [@ysbaddaden]_

### HTTP improvements

We merged numerous improvements and bug fixes for HTTP.

- `#remote_address` and `#local_address` moved from `HTTP::Request` to `HTTP::Context` ([#17196])
- Add `HTTP::Headers#merge` ([#17326])
- Serialize `IO::Memory` in HTTP body with `Content-Length` header ([#17388])

Bug fixes:

- Reject unrecognized HTTP `Transfer-Encoding` header ([#17140]), invalid `Content-Encoding` ([#17262]), and invalid HTTP trailer ([#17337])
- **[breaking]** Fix the return values of `HTTP::Request#body=` and `#content_length=` ([#17257], [#17273])
- Fix `HTTP.parse_headers_and_body` to not raise with `without_zlib` ([#17272])
- Validate properties of `HTTP::WebSocketHandler` ([#17235]), `HTTP::Request` ([#17255],[#17304], [#17374], [#17310], [#17312], [#17258]), `HTTP::Headers` name ([#17317])
- Close `HTTP::Client` on `IO::Error` during request ([#17318])
- Fix `Content-Encoding: deflate` ([#17261])
- Fix `HTTP::Request.from_io` parsing empty header name ([#17254])
- Fix `HTTP::Request#form_params?` to ignore invalid content-type ([#17256])

_Thanks [@straight-shoota], [@hahwul], [@jgaskins], [@Sija]_

### Eventloop

All targets support a native event loop based directly on the system selector and use it by default.

We enabled `epoll` on Solaris ([#17370]) and `kqueue` on all remaining BSD targets ([#17421], [#17420]).
`libevent` is still available as a fallback, but now it's strictly opt-in and becoming technically obsolete. We expect to deprecate in a following release.

_Thanks, [@ysbaddaden]_

[#17370]: https://github.com/crystal-lang/crystal/issues/17370
[#17420]: https://github.com/crystal-lang/crystal/issues/17420
[#17421]: https://github.com/crystal-lang/crystal/issues/17421
